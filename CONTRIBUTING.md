# Contributing to TuneTidy

Bug reports, feature ideas, and pull requests are all welcome.

## Reporting a bug
Open an issue with: what you expected, what happened instead, and (if relevant)
the exact error text from the app's log or GitHub Actions. Screenshots help a lot.

## Suggesting a feature
Open an issue describing the use case, not just the feature — it's easier to
figure out the right design when the actual problem is clear.

## Pull requests
- Keep changes focused — one feature or fix per PR is easier to review.
- Test that `python main.py` still runs before submitting.
- Describe what changed and why in the PR description.

## Good first contributions
See the [Known Limitations](README.md#known-limitations) section in the README —
those are genuine, scoped gaps that would make solid first PRs.
